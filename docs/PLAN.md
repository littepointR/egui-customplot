# egui-customplot 项目规划

## 0. 状态与建议默认值

- 当前目录原为空目录；本轮只建立规划，不创建实现或锁定依赖。
- 推荐定位：可嵌入 egui 应用的二维科学 / 工程绘图库，而非独立绘图软件。
- 推荐首测平台：Windows 桌面；核心模块避免绑定窗口系统，后续验证 Linux / macOS / Web。
- MATLAB 是功能与交互参考，不是语法兼容目标；不引入全局 `gca` / `gcf` 式隐式状态。
- 先完成小而正确的版本，再按测量结果优化。下述性能数字均为候选目标，不是实测结论。
- 全量图类型以 [MATLAB 绘图类型交付对照表](MATLAB_PLOT_CHECKLIST.md) 为准：冻结 R2026b 官方总览 82 项，补充 35 项本体能力和 16 项传统接口，共 133 项函数 / 方法 / 能力对照；工具箱另行分账，不混为本体。

### 1.2 首个可用版本的范围

折线、散点、多曲线叠加、线性 / 对数轴、标题与标签、图例、网格、缩放平移、数据提示，以及基本颜色、线型、线宽、标记配置。

首版暂不做：3D、曲面与体绘制、完整 LaTeX 排版、MATLAB 脚本解释器、GUI 拖拽编辑器、远程数据协议和通用插件系统。后续需求明确后另立里程碑，不提前为其扩大内核。

**首版边界不等于长期功能删除。** 按用户要求，完整绘图类型已全部纳入交付对照，其中三维、体数据、极坐标、地理、统计与网络图安排在后续阶段。全量对照不代表 MATLAB 调用语法兼容，也不代表已经冻结所有工具箱产品范围。

## 2. 架构方案

```text
用户 API：Figure / Axes / Series / Theme
                    │
       显式模型、稳定 ID、版本号与更新接口
                    │
      坐标变换 / 刻度 / 布局 / 交互 / 拾取
                    │
       可见数据查询 / LOD / 缓存 / 渲染准备
                    │
         共享的绘制命令与有序图层
            ┌───────┴────────┐
       egui Painter      可选 wgpu 后端
            │                │
            └──── egui Widget ┘
                    │
             宿主 egui 应用

导出：复用坐标、布局与场景语义，单独制定精度和字体策略。
```

### 2.1 核心决策

1. **持久模型 + 即时 UI。** 数据、视图范围、选择状态、缓存不随每帧重建；egui 负责布局调用、输入和展示。针对 egui 多遍布局，同一帧的数据追加与交互副作用不得重复执行。
2. **数据与显示分离。** 数据坐标使用 `f64`；裁剪、局部原点变换后再转成屏幕 / GPU 精度，避免大时间戳导致精度损失。
3. **先用 Painter 跑通。** 先验证数学与交互，提前保留渲染边界，但不一开始构建庞大的通用渲染框架。
4. **GPU 按证据引入。** 通过 egui 的自定义绘制回调接入 `egui-wgpu`，仅在基准确认收益后成为重点；它不能替代可见性查询与数据精简。
5. **不默认 fork `egui_plot`。** 将其作为能力和性能对照。推荐独立管理数据、坐标和样式，以便控制后续行为；具体复用部分在第一阶段的小原型中判断，不预设现有库无法满足需求。
6. **不暴露可变缓存内部。** 数据通过追加 / 替换 / 显式失效更新；稳定 ID 加版本号关联缓存，防止原地修改后显示旧结果。
7. **独立于 eframe。** 库可嵌入普通 egui 项目；示例应用使用 eframe。可选 wgpu 功能要求宿主使用兼容后端，不兼容时明确报错或使用可用的 Painter 路径，不允许静默缺图。

### 2.2 目录演进

先采用一个库包加一个演示程序的 workspace，不立即拆成大量 crate：

```text
Cargo.toml
crates/egui-customplot/
  src/
    model/          # Figure、Axes、Series、样式与 ID
    data/           # 数据源、版本、范围查询、LOD
    axis/           # 坐标变换、范围、刻度与格式化
    layout/         # 标签、图例、绘图区和子图布局
    interaction/    # 导航、拾取、选区与事件
    render/         # 绘制命令、Painter、后续可选 wgpu
    widget.rs       # egui 集成
  tests/
  benches/
examples/demo/      # 可运行的参考案例与性能场景
docs/
```

模块只随实际功能创建。第一阶段主要落地 `model`、`axis`、`render` 和最小 widget；未来只有编译依赖或复用需求足够明确时才继续拆包。

### 2.3 egui 集成与资源约束

详见 [egui 集成、性能与资源占用约束](EGUI_INTEGRATION_AND_PERFORMANCE.md)。该文档补充 10 项 egui 集成契约与 12 项性能 / 占用验收场景，目前均未实现或验证。

- 复用宿主 Ui、Response、布局、输入、局部样式、字体与渲染器，不另建窗口、Context、事件循环或 GPU device。
- 多遍布局不能重复消费输入、追加数据、发布事件或提交任务；最终布局仍须正确参与绘制。
- 静止图不主动维持连续重绘；流式请求有界合并；图表不替换宿主 repaint callback。
- 原始数据、视图状态、CPU 缓存、GPU 资源和后台任务分离持有，分别计量、限额与释放。
- 首阶段即建立诊断与空白宿主基线；Painter 和 wgpu 的 CPU 准备、提交、上传成本分别测量，不能以缓存命中代替测量。

## 3. 可定制化的具体含义

- **属性覆盖：** 库默认值 → Theme → Figure → Axes → Series；未设置与显式设置必须区分。
- **坐标轴：** 范围、缩放类型、方向、刻度位置、标签格式、主次网格、轴线与标签样式。
- **图元：** 颜色、透明度、线宽、虚线、连接与端点样式、标记形状与大小、绘制顺序、可见性。
- **布局：** 内外边距、绘图区比例、图例位置与空间占用；后续支持子图间距和色条。
- **交互：** 开关和配置缩放 / 平移、限制轴方向、自定义提示格式、读取选择与视图变化事件。
- **扩展：** 优先提供刻度格式器、数据提示格式器和标注绘制入口；出现第二个真实用例后再稳定自定义图元 trait。
- **两种使用方式：** 常用绘图使用简洁 builder；复杂场景保留可更新的显式对象句柄。不先设计全局命令式兼容层。

## 4. 高性能策略与正确性边界

### 4.1 数据与缓存

- 对帧内临时绘图支持借用切片；跨帧保存的数据支持共享不可变缓冲及受控的动态缓冲，避免每帧复制整份数据。
- 初始读入允许 O(N) 校验 / 建索引，但要与稳定交互耗时分别统计；大数据的预处理不得长期阻塞 UI。
- 单调 X 折线用二分定位可见区间，保留边界相邻点以正确裁剪线段；任意顺序折线走独立、保持顺序的路径。
- 对单调 X 折线建立多层 min/max 包络或相应索引，按像素宽度查询；不能每次缩放都假借 LOD 完整扫描全部数据。
- 降采样必须保留尖峰、顺序与断线边界；NaN 段不能被连起来。任意折线不能直接套用单调 X 算法。
- 散点另行评估屏幕空间分桶 / 空间索引；密度聚合会改变表达语义，必须由用户明确选择。
- 渲染 LOD 不替代原始数据，拾取默认查询原始点；大数据拾取需索引，不能每帧线性扫描全部数据。
- 缓存键包含数据版本、视图范围、像素尺寸 / DPI、坐标轴类型及影响几何的样式；设定内存上限和淘汰策略。
- 后台计算采用不可变快照与版本校验，丢弃过时结果；只有确有收益时才引入多线程。
- 流式数据使用有界环形缓冲、批量追加与增量上传，约定覆盖旧数据和背压行为。

### 4.2 渲染

- 按图层和兼容绘制状态批处理，但不为减少 draw call 破坏透明混合与图元顺序。
- Painter 路径测量 CPU 几何构建和 egui tessellation；wgpu 路径测量缓冲更新、draw call 与 GPU 时间。
- GPU 折线需解决宽线、连接、端点、虚线、抗锯齿和裁剪，不把原生单像素线当成完整方案。
- 先优化算法和数据传输，再根据 profiling 选择 SIMD / 并行；不为了“高性能”提前引入 unsafe。

### 4.3 数学与交互正确性

- 覆盖空数据、单点、常量序列、NaN / Inf、不合法对数输入、极小与极大范围。
- 明确非有限值与对数轴非正值的断线 / 忽略及诊断策略，不允许悄悄改变原始数据。
- 检验坐标正反变换、滚轮锚点、反向轴、等比例约束、HiDPI、窗口缩放与裁剪。
- 所有优化路径均与未经 LOD 的参考路径对比；美观和速度不能掩盖数据表达错误。

## 6. 性能验收方法

先在目标电脑跑出基线，再确定发布门槛。建议使用以下固定测试条件：

- Release 构建；记录 CPU、GPU、驱动、操作系统、Rust 与依赖版本、渲染后端及电源模式。
- 固定绘图区为 1920 × 1080 物理像素；明确 DPI、曲线数、线宽和数据是否有序。
- 区分冷启动、首次加载 / 索引构建、稳定静止、连续平移缩放、持续追加五种场景。
- 预热后连续采集至少 30 秒，报告 p50 / p95 / p99；记录 CPU 帧构建、GPU 时间（若可获取）、整帧呈现间隔与峰值内存。
- CPU 帧构建耗时不包含呈现等待；另行注明 VSync，不能用锁定在 60 FPS 的展示替代内核测量。
- 基准包括纯正弦、窄尖峰、NaN 断段、乱序轨迹、散点、稠密重叠以及不断追加的数据。
- 与不降采样的正确性参考路径、同条件 `egui_plot` 对照；功能、线宽与抗锯齿差异必须说明。

候选目标：对 100 万点、单调 X、静态折线且已建好 LOD 的场景，在约定硬件上争取连续交互 p95 帧预算 ≤ 16.7 ms（60 Hz）。这个目标不等同于每帧原样绘制 100 万个点，也不覆盖任意散点或任意折线。1000 万点先作为扩展与内存压力场景，不提前承诺帧率。

资源验收不只看 FPS：按 [集成与占用约束](EGUI_INTEGRATION_AND_PERFORMANCE.md) 分账记录原始数据、CPU 缓存、GPU 申请、后台队列、空闲唤醒与分配。缓存预算不等于进程总内存；默认限额和回归门槛须基线测量后冻结，不能将规划目标描述成已测结果。

## 7. 测试与交付规则

- 单元 / 性质测试：范围、刻度、坐标往返、可见区间、LOD 的顺序 / 极值 / 断段、缓存失效与环形缓冲。
- 集成测试：多帧状态、交互事件、重复布局、DPI 变化与宿主嵌入。
- 视觉回归：固定字体、DPI、种子与渲染设置；对 GPU / 驱动差异使用有说明的容差，不要求跨平台逐像素相同。
- 性能回归：微基准和应用级基准分开；普通 CI 不作为 GPU 帧率裁判，固定硬件结果单独记录。
- 导出：复用模型、布局和场景语义，但不承诺与屏幕后端像素级一致；明确文本嵌入 / 转路径策略和导出 LOD 精度，避免把屏幕缩略结果直接当高质量输出。
- 每个里程碑交付：运行命令、示例、测试结果、基准条件、已知限制及下一步。
- 每个图类型按 [完整交付对照](MATLAB_PLOT_CHECKLIST.md) 的稳定 ID 关联案例、正确性、样式 / 交互、性能和导出证据；仅能画出外形不能标记为已交付。

## 8. 待确认事项

以下均为未知项，暂用第 0 节默认值推进规划，不视为已经得到用户确认：

1. 优先面向离线科学分析，还是实时仪器 / 信号监控？默认两者共用内核，先用静态科学绘图验证正确性。
2. 典型数据规模、曲线数、采样率和实际硬件是什么？这决定性能门槛及优化顺序。
3. 首版是否必须包含多子图、双 Y 轴或热力图？若必须，应调整第二阶段范围。
4. 是否要求 Web、已有 egui / eframe 版本、指定渲染后端和最低 Rust 版本？
5. 是否需要中文标签、数学公式和论文级矢量输出？默认支持用户注入字体，完整公式排版暂缓。
6. 发布许可证与 crate 名称尚未确定；规划不等于同意具体许可证。
