# 阶段 1：可运行的二维折线原型

日期：2026-11-15。仓库：[littepointR/egui-customplot](https://github.com/littepointR/egui-customplot)，**私有**。

这是首个代码切片，不是完整 0.1、MATLAB `plot` 兼容实现或长期性能验收结论。

## 已实现

| 模块 | 本轮能力 |
| --- | --- |
| `PlotData` | 不可变 `Arc<[[f64; 2]]>`，一次扫描缓存有限点范围；克隆共享样本；非有限点断段 |
| `PlotBounds` / `PlotTransform` | 有限、非退化 f64 范围；线性正反变换；局部原点相减后才转 f32；自动范围与常量数据展开 |
| `Line` / Painter | 多折线叠加、颜色 / 线宽、f64 段裁剪、父 Ui 裁剪；只输出当前可见线段，但仍遍历所有段 |
| `PlotState` | 显式、独立视图；自动 / 手动范围；同数据多视图不共享导航 |
| `Plot::show` | 原生 Ui 空间分配、稳定 ID、Response、局部主题 / 字体、基础固定分隔网格与数字标签 |
| 导航 | 拖动平移、悬停滚轮锚点缩放、双击 / 聚焦 Home / API 复位；可关闭平移或滚轮缩放 |
| 多遍布局 | 保存帧初范围与本帧导航输入，后续遍从同一基准按最终矩形重算；不会重复累计拖动或缩放 |
| 空闲与隐藏 | 不主动请求连续重绘；屏外图仍布局并保留状态，但跳过几何准备 |
| Demo | 1 千 / 1 万 / 10 万 / 100 万点、NaN 开关、基础样式、共享数据双视图；复用 eframe 的 Glow 后端 |

原始数据在宿主模型中，不在 egui Memory 中；`PlotState` 内只有导航及一份小型帧快照。帧快照保留 Context 句柄以区分不同 Context，但不保留样本引用；应把 `PlotState` 放在宿主模型中，不要反向存入同一 Context 的 IdTypeMap。销毁 state 会释放该句柄。库不创建 worker、窗口或设备，不替换重绘回调。

`PlotData` 是持久共享数据，不是每帧借用切片接口；后一种用法尚未提供。更新数据目前通过替换整个 `PlotData` 实现，构造 / 扫描为 O(N)，应在显示前完成。没有流式追加、后台预处理和取消协议。

### 当前可定制范围

绘图高度、背景色、网格开关、平移开关、滚轮缩放开关、每条折线颜色 / 线宽、显式手动范围。字体和背景默认读取局部 egui 样式；折线默认使用固定的三色循环。尚无完整 Theme → Figure → Axes → Series 继承、虚线、标记或格式化回调。

滚轮缩放默认关闭以保留 ScrollArea 的滚动；启用后只消费悬停、无修饰键的竖向平滑滚轮。Ctrl / cmd 滚轮留给 egui 全局缩放，尚未提供独立触控 pinch 或轴向限制。`view_changed` / `Response::changed` 是本遍结果，**不是可重复执行闭包中的一次性事件队列**；在 `run_ui` 返回后读取最终 `PlotState` 再驱动外部副作用。

## 性能诊断：不把局部计数当成总占用

每次 `show` 返回输入点数、非有限点数、访问段数、输出点 / 路径数、按共享缓冲去重的样本有效字节、屏幕点 Vec capacity 字节，以及几何准备 + Shape 提交时间。

- 样本字节不含 Arc 头、分配器、宿主对象和 GPU 副本。
- 几何字节不含路径容器头、egui 生成的顶点 / 索引和临时工作区，不是进程 RSS 或峰值内存。
- 准备时间不含坐标轴标签、egui tessellation、GPU 上传、绘制或 present。
- 多遍布局按遍计数，被丢弃遍也可能做了工作；不是整个 frame 的累计计数。
- 所有几何逐遍重建；没有 LOD、区间索引、跨帧几何缓存、内存硬预算或上传计数。

### 首份 CPU 基线

基准源码：[frame_baseline.rs](../crates/egui-customplot/benches/frame_baseline.rs)。实测记录放在 [benchmarks/](benchmarks/)。

条件：Windows x64 10.0.26300、Intel Core i9-14900KF（32 逻辑处理器）、Rust 1.100.0 / LLVM 23.1.5、egui 0.37.0、bench 优化构建；画布 2024×1124，绘图区 1920×1080，1 point = 1 pixel。30 帧预热后每场景采样至少 30 秒；10 万个单调 X 正弦点、线宽 1.5、单曲线。空白 egui 场景没有控件，空图场景包含坐标与背景。

**这是无窗口、无 renderer、无 VSync 的 CPU 基线，不存在被测 GPU 后端。** GPU / 驱动、电源模式和系统其他负载未完整记录，不能作为固定硬件发布门槛，也未与 `egui_plot` 对比。UI 构建和 tessellation 分别计时；`total` 是两者的单样本和，不是两个 p95 相加。内存释放、采样数组维护、平移场景的 `set_bounds`、GPU 上传及呈现不在该计时内。基准自身保留耗时样本数组，不能把它的进程内存当成图表内存。

关键可验证事实：10 万点场景每次仍访问 **99,999 段**，几乎全部点仍交给 egui；tessellation 不能因缓存范围而消失。后续优化应先引入正确保留峰值 / 断段的可见区间查询与 LOD，再用相同脚本对照，不能据本轮 CPU 子集换算真实 FPS。

## 已知限制与下一步

1. **不是 MATLAB `plot` 完整交付。** 无标记、复数输入适配、图例、对数轴、数据提示和导出；ML-001 保持“开发中”。
2. 单点 / 被非有限值隔离的单点没有线段，因此不画点标记。NaN 和 Inf 都断段，不仅 NaN。
3. 自动范围若跨度溢出或不能表示为有限正值，返回默认视区并设置 `auto_bounds_error`；不会宣称支持任意 f64 动态范围。导航到退化范围会被拒绝；归一化溢出的段跳过并计入 `numeric_rejections`。极端数值 / 极深缩放的裁剪精度仍需加强。
4. 刻度只是每轴五个固定分隔值，不是自适应 nice ticks。大偏置 / 极窄范围可能显示重复标签，极小控件的标签可能相互覆盖；保持父容器裁剪，但不承诺完善排版。
5. 启用滚轮缩放的控件会消费悬停滚轮，这是显式选择；多遍布局中极端的容器重排与输入仲裁仍有后续测试空间。
6. 没有流式缓冲、资源预算、后台任务、GPU 资源计数、30 分钟流式 / 整进程内存 / 显存与功耗测量，不承诺百万点 60 Hz。
7. 首测 Windows 桌面；Linux 仅配置 CI，macOS / Web 未验证。没有开源许可证，不发布 crates.io。

下一切片：自适应刻度 / 标签与图例、散点、对数坐标和数据提示；同时扩充数值与交互测试。在阶段 4 增加 LOD 和有界资源机制，不提前把规划中的能力标为已实现。
