# egui 集成、性能与资源占用约束

## 1. 状态与原则

**本文是设计与验收约束，不是实测报告。** 阶段 1 已有可运行的折线原型，基础测试与首份 CPU 基线见 [首轮记录](STAGE_1.md)；仍未满足本文所有约束。仅有“Widget + 可选 GPU”不足以证明充分集成，也不能证明高性能或低占用。

目标是：**对外像原生 egui 控件，对内是有界、可测、按变化更新的绘图内核。** 不另建 GUI 框架，不把所有图类型和专业计算默认塞入最小依赖。

性能由三部分共同决定：库的算法与资源管理、宿主的事件循环 / 其他 UI、目标设备及驱动。库可以约束自身工作量与申请的资源，不能保证任意用户回调、宿主或硬件上的整帧耗时。

## 2. egui 原生集成契约

以下是完整目标，最新 `EGUI-01`～`EGUI-10` 与 `PERF-01`～`PERF-12` 全量逐项核销结论及开放边界见 [阶段 11 全量核销](STAGE_11.md)，历史首轮与专项证据见 [首轮记录](STAGE_1.md) / 各阶段报告。

| ID | 结合点 | 设计要求 | 验收方式 |
| --- | --- | --- | --- |
| EGUI-01 | 原生嵌入 | 通过 `&mut egui::Ui` 显示，使用 egui 的空间分配、`Sense` 与 `Response`；复杂返回值保留原始 Response | 在 Panel、Window、ScrollArea、Grid 和外部标签页容器中运行；不要求宿主采用 eframe |
| EGUI-02 | 布局与裁剪 | 绘图区服从父 Ui 的裁剪及可用尺寸；内部把数据区、轴标签、图例分别布局 | 滚动裁剪、极小窗口、折叠、缩放 / DPI 切换；不越界、不留下错误命中区域 |
| EGUI-03 | ID 与状态 | 图表和序列使用稳定 ID；不同视图共享数据而不共享导航状态；按 viewport / widget / 数据版本区分相关缓存 | 同数据双视图、同屏多图、列表重排、移除重建和多 viewport 不串状态 |
| EGUI-04 | 输入仲裁 | 使用 egui 的命中、拖动、焦点和禁用状态；悬停 / 修饰键规则决定滚轮归属，键盘动作要求合适焦点 | 与 ScrollArea、拖动容器、文本输入、弹窗 / 菜单共存；图外滚轮不缩放图；不绕过遮挡层抢输入 |
| EGUI-05 | 多遍布局 | `show` 可在同一帧多次调用；交互计算可重入，追加、事件与后台提交不可重复应用 | 强制布局重跑；一帧滚轮 / 拖动只改变一次视图，数据只追加一次，外部事件只消费一次 |
| EGUI-06 | 主题与字体 | 默认读取当前 Ui 的样式、Visuals、字体与 egui 点单位；图表主题支持覆盖但不修改宿主全局样式 | 局部样式、系统深浅主题、中文字体、UI 缩放、HiDPI 和混合主题共存 |
| EGUI-07 | 原生 UI 扩展 | 图例开关、提示、右键菜单、属性面板用普通 egui 控件；事件返回宿主，用户回调不在 Context 锁内执行 | 用户能向菜单 / 提示中加入任意 egui UI；回调可安全调用 egui API |
| EGUI-08 | 重绘调度 | 仅在输入、数据变化、动画或任务完成时请求重绘；定时动画使用延迟请求，后台请求面向正确 viewport | 静止图不主动维持连续重绘；后台可唤醒正确窗口；不替换宿主 repaint callback |
| EGUI-09 | 渲染与资源 | Painter 使用宿主绘制链；wgpu 回调使用宿主 device / queue / renderer 与有序图层 | 没有第二个窗口、Context、事件循环或重复 GPU device；前后叠放的 UI 和透明图元顺序正确 |
| EGUI-10 | 可访问性与生命周期 | 暴露有意义的 widget 信息与键盘操作；大数据用摘要 / 选中点而非为每点创建 UI 节点；数据、视图、渲染资源可独立释放 | 焦点 / 键盘测试；销毁图表、关闭 viewport、重建渲染器后无资源或任务持续累积 |

### 2.1 状态归属与多遍布局

- **宿主模型持有原始数据。** 数据切片可借用，共享数据可用不可变缓冲句柄；不把百万点数据或 GPU 对象塞进 `egui::Memory` / `IdTypeMap` 做自动持久化。
- **显式 PlotState 持有视图状态。** 包括范围、选区和交互会话。小型控件状态可按 ID 存储，但所有权和回收方式必须明确。
- **受预算控制的缓存持有派生数据。** 数据索引、LOD、布局和几何不能因为隐藏在 Context 中而没有释放路径。
- **渲染器持有 GPU 资源。** 资源标识包含设备 / 渲染器代次，不能把旧设备的句柄复用到新 renderer。
- 同一帧的各遍布局从一致的交互基准快照推导候选视图，不能在每遍都累计 `drag_delta` / 滚轮值；同样不能简单“只运行第一遍”而忽略最终布局尺寸。
- 数据追加原则上在显示前通过明确更新接口执行；对外事件带稳定去重标识。多遍布局的最终提交 / 事件消费协议在第一阶段原型中验证，不假设用户的 UI 闭包只调用一次。
- `Ui::is_rect_visible` 可用于跳过重绘几何等昂贵工作，但不可据此跳过必要布局或错误清空状态；egui 在被丢弃的布局遍中也可能返回不可见。
- 窗口最小化 / OS 遮挡由宿主提供可见性信息；图表不宣称仅靠矩形裁剪就能判断所有系统级遮挡。

### 2.2 不接管宿主

库不调用宿主的 `run_ui` / tessellate / present，不设置全局字体或样式，不替换 `set_request_repaint_callback`，不为每张图创建线程池，也不要求用户采用专用应用基类。

非 eframe 宿主需按 egui 契约接好唤醒和绘制；数据生产快于显示时合并绘图请求，不给整个 UI 强行限帧。用户输入仍应及时响应。限制显示刷新不等于丢弃采样数据，丢弃 / 覆盖 / 背压策略必须明确配置。

## 3. 性能：控制工作量，而不是只追求 GPU

### 3.1 帧路径

```text
外部数据更新（追加 / 替换 / 版本变化）
             ↓
索引 / LOD 构建或增量更新（大任务可后台、有预算）
             ↓
egui show：布局 → 命中与交互 → 可见区间查询
             ↓
按视图与物理像素规模准备数据 → 复用或更新几何
             ↓
提交 Painter 图元 / wgpu 回调 + egui 标签 / 图例 / 提示
```

- **不每帧全量复制 / 扫描。** 原始数据范围在版本变化时计算，不因自动坐标轴而每帧 O(N) 扫描；LOD、拾取索引和统计也不能悄悄落回热路径全扫描。
- **只处理需要显示的数据。** 单调 X 折线先二分可见区间，再查层次化 LOD，按物理像素宽度选择数据。保留边界相邻点、尖峰、顺序与断段。
- **不夸大复杂度。** 对少量连续分段的单调 X 折线，准备点数争取与像素宽度相关；大量断段、任意轨迹和散点需各自算法，不能统一承诺 O(屏幕宽度)。
- **避免每点一个 UI / 绘制对象。** 同类图元批量提交，不为百万样本创建百万控件或百万个小 Shape。散点仍需注意填充率，实例化本身不能消除严重重叠的开销。
- **重计算只在必要时发生。** 十字线移动不重建全图；颜色变化不无条件重算统计与 LOD；范围变化不重新读取或复制原始数据。
- **后台也要有界。** 工作池按需共享；限制并行数、排队任务及结果快照。过时任务尽早取消 / 丢弃，不能只丢结果却让无限计算继续占 CPU。
- **显示版本一致。** 新数据预处理未完成时，若暂时显示旧快照，须可诊断 / 标示；不得混用新轴、新提示与旧图形产生误导。
- **用户回调有成本。** 刻度格式器只按实际刻度调用；对可缓存结果提供失效机制。任意自定义回调 / 图元 / shader 的耗时不可能由库替用户保证。

### 3.2 按变化分类失效

| 变化 | 预期更新 | 应避免的工作 |
| --- | --- | --- |
| 数据追加 / 替换 | 更新范围、索引、LOD、受影响几何 | 对小批追加全量重建历史数据 |
| 视区缩放 / 平移 | 可见查询、刻度、投影、必要几何 | 重建与视区无关的数据索引 |
| 字体 / DPI / 图例布局 | 文本与布局、像素相关 LOD / 几何 | 重算原始统计和几何拓扑 |
| 线宽 / 虚线 | 相应线条几何或 shader 参数 | 无条件重新读取整份数据 |
| 颜色 / 可见性 | 必要的材质 / 图例 / 绘制集合；若有颜色聚合则更新相关缓存 | 无关坐标索引与统计计算 |
| 悬停 / 选择 | 索引拾取、提示与高亮覆盖层 | 全量数据扫描与静态图层重建 |

### 3.3 Painter 与 wgpu 的实际边界

- Painter 是首个正确性与集成后端，不是承诺低成本的“保留式画布”。即使缓存几何，egui 每次绘制仍需提交图元，可能进行 tessellation、批处理和上传；缓存命中不能直接等同于 GPU 零上传。
- wgpu 适合需要持久缓冲、大批量散点、三维 / 体数据等路径。复用宿主 device / queue，在 prepare 阶段更新资源，在 paint 阶段绘制；不每帧创建 pipeline / 大纹理。
- GPU 回调需要拥有安全的跨阶段资源句柄；不能为了满足生命周期每帧 `to_vec` 复制整份借用数据。回调只捕获必要快照，防止旧数据 / 大缓冲被意外长期引用。
- 数据追加或局部修改优先增量上传；图像可使用局部纹理更新。实际上传量和分配量必须计数，不能只凭设计声称“零拷贝”。
- 批处理不能改变透明混合顺序、裁剪和 UI 遮挡；宽线、虚线、连接、端点与抗锯齿均需验证。

## 4. 内存、显存与后台资源：分账和硬边界

### 4.1 统计边界

至少分别暴露以下逻辑计数，不仅提供一个笼统的进程内存值：

1. 原始数据：借用 / 共享 / 本库拥有的有效长度、capacity 和字节数；共享缓冲按资源身份去重统计。
2. CPU 派生资源：索引、LOD、统计、布局、屏幕几何、临时构建区及缓存保留容量。
3. GPU 申请资源：顶点 / 索引缓冲、纹理、深度 / 多采样附件、暂存及未完成帧引用的资源。
4. 后台资源：任务数、输入队列字节、未消费结果、被任务保留的旧快照。
5. 宿主 / 驱动额外开销：单独观测进程 live allocations、private bytes / working set 及可获取的 GPU 内存指标。

例：100 万个 `[f64; 2]` 的原始 XY 有效数据为 16,000,000 字节，约 **15.3 MiB**。这不是整个图表的内存需求，不包含容器多余容量、索引、LOD、几何、GPU 副本或驱动分配。等间隔 X 可采用隐式 X 数据源减少存储；这属于明确的数据表示，不是隐式丢精度。

`Arc` / 借用只减少 CPU 侧不必要复制，不等于索引、派生数据和 GPU 上传也不占内存。`Arc::make_mut` 在仍有共享快照时可能触发整份复制，流式缓冲必须避免误用。

### 4.2 资源预算

| 资源 | 约束策略 | 超限行为 |
| --- | --- | --- |
| 原始数据 | 借用 / 共享不额外克隆；库拥有的数据可配置容量和接纳策略 | 明确拒绝、背压或按已选窗口覆盖；不擅自丢弃科研数据 |
| CPU 缓存 | 全局预算 + 每图预算，按实际容量计费，淘汰旧视区 / 旧版本 | 先淘汰派生缓存，再降低允许的缓存规模或返回受控错误 |
| GPU 资源 | 申请前估算、全局预算、按需复用；计入暂存和仍被帧引用的旧缓冲 | 分块 / 可接受的 LOD / 后端回退或明确失败，不能无限新建 |
| 临时构建区 | 限制峰值容量，分块处理；后台结果入缓存前做接纳检查 | 暂缓 / 取消 / 分块，不先分配巨量内存再检查预算 |
| 流式队列 | 有界队列 + 有界环形缓冲，批量消费 | 使用配置的背压 / 覆盖策略，并暴露丢弃计数 |
| 后台计算 | 限制 worker 数、并发任务和等待结果数，视图任务可合并 | 取消旧视图任务；数据更新与可丢弃视图任务采用不同策略 |

预算只约束本库控制的资源。调用方持有的原始缓冲、egui 字体图集、宿主其他 UI、分配器和驱动开销不受该缓存预算直接控制。GPU 申请字节可追踪，但不等于驱动真实驻留显存；不能宣称配置 64 MiB 缓存就能让整个进程只用 64 MiB。

### 4.3 释放、空闲和体积

- 视图销毁 / 数据替换时撤销关联任务和缓存引用；纹理 / 缓冲按所有权释放。GPU 释放可能需等待提交完成，测试必须计入在途帧。
- 允许为复用保留容量，但计入预算；提供显式清缓存 / 内存压力收缩入口，不能以“缓存”为由无限增长。
- 静止图不自行请求连续 repaint；流式数据按显示节奏合并唤醒，隐藏图停止无意义的几何准备 / 上传，数据是否继续采集由宿主决定。
- 最小功能集只引入必要的 egui 与基础图元。统计、极坐标、图网络、三维、体数据、地理、导出、wgpu、配置序列化采用按需 feature / 模块边界，最终依赖关系实施时确定。
- eframe 只用于演示宿主，不成为库必须的运行时依赖；不默认开启地图网络请求、线程运行时、大型字体包或专业分析工具链。
- 检查 feature 展开、重复 egui / wgpu 版本、最小 / 完整构建的耗时、产物大小与目标平台能力；feature 名称不是已经存在的 Cargo 配置。

## 5. 如何验收，而不是靠口头保证

所有测试都先有固定机器和空白 egui 宿主基线；库的增量开销与整应用总开销分开。Release 构建、固定 DPI / 物理像素、明确 VSync、预热后采样，遵循 [项目性能验收方法](PLAN.md)。

| ID | 场景 / 指标 | 通过条件或处理方式 |
| --- | --- | --- |
| PERF-01 | 帧耗时 | 分开记录布局、刻度、查询 / LOD、几何、tessellation、上传、GPU、呈现；报告 p50 / p95 / p99；不可只看 FPS |
| PERF-02 | 数据规模 | 1 万 / 10 万 / 100 万 / 1000 万点分档；区分预处理与热路径；按图类型确定适用规模 |
| PERF-03 | 隐藏工作量 | 记录每帧扫描 / 查询 / 输出点数、顶点数、draw call、上传字节、缓存命中、分配次数 / 字节 | 
| PERF-04 | 多图共存 | 测试单图、4 图、16 图以及滚动区域中的屏外图；不把单图性能直接当仪表盘性能 |
| PERF-05 | 空闲 CPU / GPU | 无输入、无数据变化、无动画时，库在布局稳定后不持续主动请求重绘；测量相对空白宿主的 CPU 时间、GPU 活动和唤醒 |
| PERF-06 | 流式负载 | 输入快于显示、连续追加至少 30 分钟，队列 / 历史 / 快照均有界，丢弃和背压可观测 |
| PERF-07 | 资源释放 | 大数据图重复创建 / 销毁至少 100 次，完成任务并排空 GPU 在途工作后，存活对象和申请资源回到约定范围，不随轮数持续增长 |
| PERF-08 | 交互压力 | 连续缩放 / 平移、窗口拖动 / DPI 变化、任务取消和数据替换，既测长帧也测结果正确性 |
| PERF-09 | 样式压力 | 修改颜色、线宽、字体、主题、图例；用失效计数验证没有误触发全量数据重建 |
| PERF-10 | 预算与故障 | 故意限制 CPU / GPU / 队列预算并制造分配失败，验证受控降级 / 错误；不静默更改数据语义 |
| PERF-11 | 产物与依赖 | 最小 / 完整 feature 构建分别记录依赖、编译耗时与产物大小；专业功能关闭时无隐式网络 / worker 活动 |
| PERF-12 | 性能回归 | 固定硬件复测稳定基线，冻结每场景门槛后设回归检查；普通 CI 检验算法、资源计数和生命周期，不代替 GPU 实机测试 |

验收补充：

- 百万点 60 Hz 仍只是候选目标：单调 X、静态折线、已建 LOD、约定硬件，争取交互 p95 帧预算 ≤ 16.7 ms。不覆盖所有图类型，也不是声称每帧完整画出百万点。
- CPU 缓存预算、GPU 申请预算、并发任务数和流式窗口应是可配置的有限值；具体默认值需第一阶段基线和目标设备信息后确定，不凭空承诺一个总内存数字。
- RSS / working set 不立即下降不一定是泄漏，分配器和驱动可能保留内存；因此同时检查存活分配、引用、GPU 资源和长期增长趋势。反之，仅 RSS 稳定也不能证明没有资源泄漏。
- 若要降低显示精度或聚合数据，必须使用明确的策略并保留原始数据与可追溯性；性能未达标不能靠隐藏缺失点、峰值或统计差异来通过。
- 本文只提供未来测量字段，不填写虚构的测试结果。第一阶段即接入诊断与空白宿主基线，不能到全类型完成后才开始测性能。

- [Context](https://docs.rs/egui/0.37.0/egui/struct.Context.html)：UI 闭包可能多遍执行；`cumulative_frame_nr` 与 pass 计数不同；内部访问持锁，回调中不可递归锁同一 Context。
- [request_repaint](https://docs.rs/egui/0.37.0/egui/struct.Context.html#method.request_repaint) / [request_repaint_after](https://docs.rs/egui/0.37.0/egui/struct.Context.html#method.request_repaint_after)：按需及延迟重绘；请求可以被其他事件提前，不是硬性限帧器。
- [set_request_repaint_callback](https://docs.rs/egui/0.37.0/egui/struct.Context.html#method.set_request_repaint_callback)：唤醒由宿主接线，重复设置会覆盖原回调，库不能擅自接管。
- [Painter::with_clip_rect](https://docs.rs/egui/0.37.0/egui/struct.Painter.html#method.with_clip_rect)：绘图区裁剪与父裁剪相交。
- [TextureHandle::set_partial](https://docs.rs/egui/0.37.0/egui/struct.TextureHandle.html#method.set_partial)：局部纹理更新接口。
- [egui-wgpu CallbackTrait](https://docs.rs/egui-wgpu/0.37.0/egui_wgpu/trait.CallbackTrait.html)：在宿主渲染流程中 prepare / paint，复用 renderer 资源与 render pass。
